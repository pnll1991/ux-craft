# Website playbooks

Choose the playbook that matches the page or flow. Do not force every site into the same landing-page pattern.

## Service landing

Clarify the problem, the proposed work, scope boundaries, proof that is actually available, and the next action. Keep pricing, constraints and conditions close to the decision they affect. Starting principles: selective attention, cognitive load, Hick–Hyman, serial position, peak–end.

**Done when:** a visitor can explain the offer, who it is for, what happens next, and any important condition without hunting through the page.

## SaaS / product

Explain the job the product performs before feature density. Make plans comparable, show real states, and keep onboarding skippable. Starting principles: mental models, Jakob, active user, choice overload, goal-gradient.

**Done when:** a new user can reach the first useful outcome without mandatory education and a returning user can move efficiently.

## Commerce

Make product differences, total cost, availability, delivery and return conditions visible before commitment. Preserve cart state and recover from payment failure. Starting principles: choice overload, proximity, working memory, Fitts, peak–end.

**Done when:** a shopper can compare, choose, review the full consequence, recover from errors and know whether the order actually completed.

## Dashboard

Prioritize the task over decorative metrics. Make scope, filters, timestamps and permission boundaries explicit. Separate viewing from consequential bulk actions. Starting principles: selective attention, working memory, common region, mental models, Pareto.

**Done when:** a user can identify current scope, interpret freshness and execute a scoped action without accidentally affecting hidden records.

## Forms / booking / checkout

Ask only for information required for the action. Use persistent labels, useful validation, editable review, honest progress and recoverable errors. Starting principles: proximity, Postel, Fitts, goal-gradient, peak–end.

**Done when:** keyboard-only completion works, errors explain recovery, valid input is preserved, and the final state matches the backend result.

## Editorial / documentation

Optimize for finding, understanding and returning to information. Use informative headings, stable navigation, readable measure and search/indexing when warranted. Starting principles: chunking, serial position, working memory, selective attention.

**Done when:** a reader can find a specific answer, identify context/source and return without repeating the search.
